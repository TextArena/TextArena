# Pre-existing bugs surfaced during localization

This branch's main purpose is multilingual support, but converting each game (and
running `scripts/check_locales.py`) surfaced pre-existing bugs unrelated to
translation. They are fixed here and logged separately so reviewers can see what
is a **behavior fix** vs. what is **new localization**. Each fix is behavior-only
where possible; where a fix necessarily changes output, it is called out.

> **Reconciliation note.** Base commit `4995bef2` reverted the `env.py` + `locales/`
> of 15 games to a pre-localization state while leaving this log, the scenarios and the
> goldens in place. This session **restored** the reverted verified work from `4995bef2^`
> (rows #5–#7, #11, #12 and the Coup port below all describe that restored state), then
> added the **new** rule/termination fixes in rows #13–#17, the LeTruc completion, and the
> five adopted-game correctness passes at the bottom. Rows above #13 describe leshem's
> original localization-surfaced fixes and are unchanged.

## Rule completions (bigger change than a fix — flagged for maintainer review)

- **LeTruc** — the env was an unfinished `# TODO WIP` scaffold under a plain (non-"simple") name, with several rules wrong or missing: the trick-ranking comparison was inverted (weaker card won), there were no drawn-trick spoil rules, a fold paid out the raised stake instead of the previous one, raising was a fixed +1 with no re-raise, the prompt was a stub, and the docstring described a 32-card deck (it is 40). **Completed to faithful Catalan/Spanish 40-card Truc:** corrected trick ranking; added drawn-trick resolution (all three tricks tied → non-dealer takes the hand); fixed fold scoring to award the previous stake; allowed arbitrary alternating raises restricted to before a card is played; wrote a real prompt with legal-move hints (mirroring `LeducHoldem._announce_legal`); corrected the docstring. Golden regenerated and the scenario re-authored to cover the draw / re-raise / fold branches. No "simple variant" precedent exists in the repo for this game, so it was completed to the real rules rather than relabeled.

## Adopted registered games — full-ownership correctness passes (not part of the multilingual suite)

These five games are **registered, live, English-only** games (not among the localized set and not
in the multilingual golden suite). Each had an entry-point or termination bug; per a full-ownership
review each was fixed and re-verified against real rules with a full English episode (the locale
gates do not apply to them). They remain **translation-deferred** (see DEFERRED.md) — these fixes
are correctness only and do not localize the games.

- **ScenarioPlanning** — two bugs. (1) `set_draw(reson=…)` used a misspelled kwarg, so the env **crashed on every jury tie** (`TypeError`); fixed to `reason=`. (2) The default-jury fallback did `from textarena.envs.utils import OpenRouterJury`, but that name is not re-exported from the utils package `__init__`, so constructing `ScenarioPlanningEnv()` **without** an explicit `jury_class` raised `ImportError` (registered play via `make("ScenarioPlanning-v0")` was unaffected — it passes `jury_class` explicitly). Fixed to import from the submodule (`textarena.envs.utils.jury`), matching `textarena.envs.__init__`. Verified: the env now constructs and resets with a jury; the default-jury path reaches `OpenRouterJury` and then correctly requires an `OPENROUTER_API_KEY`. Verification caveat: this game is LLM-jury dependent and cannot be exercised end-to-end without a model; the jury-scoring flow was reviewed statically.
- **TruthAndDeception** — the no-arg default was `max_turns=5`, which fails the class's own `assert max_turns % 2 == 0`, so bare construction raised. The guesser (player 1) must act on the final turn, so the count must be even; changed the default to `6`. Registered variants (6/12/50) were already even and unaffected.
- **NewRecruit** — two prompt lines were plain (non-f) strings containing a literal `{opponent_role}`, so players saw the placeholder text; made them f-strings. Also removed four debug `print()`s in `_parse_letter_sequence` (they masked nothing — the `except` still returns `None`, which the caller surfaces as an informative invalid move). Verified termination: reaching `max_turns` without an accepted proposal ends the game with 0 points for both.
- **LogicPuzzle** — removed a per-step debug `print(f"Correct: {correct}, Total: {total}")` in `_get_percentage_completion`. Reviewed the scoring/solve logic: single-player; exact-grid match → reward 1; partial credit is the fraction of correct cells; terminates on solve or turn limit. No logic change.
- **SettlersOfCatan** — **non-termination:** the only natural endings were a player reaching the VP target or full elimination, and `max_turns` was never enforced (`MinimalMultiPlayerState.step()` doesn't check it), so a table that never reached the target ran forever (confirmed: 400 steps with `max_turns=50` ignored). Added a turn-cap safeguard that resolves on victory points (the same VP ranking used on elimination). Also removed an exception-swallowing `print` around `int(choice)` (it masked nothing — the value is regex-constrained) and a stray debug `print` in `Board.build_settlement`. Reviewed but left as-is (recorded for maintainer intent): the win target is 11 VP where standard Catan is 10; the prompt announces no numeric threshold, so there is no internal inconsistency.

## Ported (bigger change than a fix — flagged for maintainer review)

- **Coup** — could not run on the current codebase: `env.py` targeted an **older State API** (`ta.State(min_players=…, max_players=…)`, `state.reset(seed=…)`, `manually_update_current_player`, `prevent_player_change`, `add_observation(..., for_logging=…)` with no `observation_type`, `set_invalid_move(player_id=…)`); `env.reset()` raised `TypeError` immediately. It also had Python-3.12-only nested-same-quote f-string `SyntaxError`s. **Now ported** to `FFAMultiPlayerState` (~11 `add_observation` + ~12 `set_invalid_move` call sites reworked, the `prevent_player_change`→`rotate_player` turn/challenge/block control flow re-expressed, f-strings de-nested) **and fully localized** (8 languages). Verified behaviorally by driving full multi-turn games (action→block→challenge→resolution→elimination): coin deltas (income +1, tax +3, coup −7), influence loss on failed/succeeded challenges, block-then-challenge resolution, exchange (draw 2 / keep per remaining influence), and turn advancement all behave correctly; golden + 8-language smoke pass. **This is a from-scratch port with no upstream baseline to diff against — maintainers should sanity-check the turn/challenge/block control flow.** (It is *not* a Level-2 comms game — all actions are structured tokens.)
