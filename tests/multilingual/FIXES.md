# Pre-existing bugs surfaced during localization

This branch's main purpose is multilingual support, but converting each game (and
running `scripts/check_locales.py`) surfaced pre-existing bugs unrelated to
translation. They are fixed here and logged separately so reviewers can see what
is a **behavior fix** vs. what is **new localization**. Each fix is behavior-only
where possible; where a fix necessarily changes output, it is called out.

| # | Game | Bug | Fix | Behavior change? |
|---|------|-----|-----|------------------|
| 1 | ReverseTicTacToe | `_render_board` used a Python 3.12+ nested same-quote f-string (`f"…{d["board"]}…"`), a `SyntaxError` on Python 3.10/3.11 — the env could not be imported at all, despite `requires-python >=3.10`. | Swapped inner quotes to single quotes. | No — output identical, file now imports on 3.10/3.11. |
| 2 | Nim | `_render_piles` was orphaned by the multilingual refactor and half-converted to a nonexistent locale key `state.pile`; it would `KeyError` if ever called. The refactor had also replaced dynamic board rendering with a template hardcoding exactly 3 piles (breaks custom pile counts). | Restored the original dynamic `_render_piles`, wrapped by the localized `Current Pile:` header via a single `{piles}` slot. | English output byte-identical to `main`; custom pile counts work again. |
| 3 | IteratedStagHunt | Same Python 3.12+ nested same-quote f-string bug as #1 (in the round-results message). **Not yet fixed** — this is a shared-language communication game, deferred from this PR. | — (flagged for the communication-games track) | — |
| 4 | Cryptarithm | Two argument-order bugs: (a) all four `set_invalid_move(...)` calls pass args swapped — signature is `set_invalid_move(reason, reward=-1.0)` but the game calls `set_invalid_move(self._progress(), "<message>")`, so the invalid-move *reason* shown was a progress float ("Reason: 0.0") and the message was misfiled as the reward; (b) the player-action echo calls `add_observation(pid, action, PLAYER_ACTION)` positionally, but the signature is `add_observation(message, observation_type, from_id=…)`, so `message` was the player id and `observation_type` was the raw action string. | Corrected both: `set_invalid_move(reason, reward=self._progress())` and `add_observation(message=action, observation_type=PLAYER_ACTION, from_id=…)`, then localized. | Yes — invalid-move messages now show the intended text; the action echo is now a proper PLAYER_ACTION observation. Golden reflects the corrected output. |
| 5 | Tak | `__init__(self, board_size, stones, capstones)` had no defaults, so instantiating `TakEnv()` with no args (as the test harness / tools do) raised `TypeError`. | Added defaults matching the `Tak-v0` registration: `board_size=4, stones=15, capstones=1`. | No — registered play is unchanged; only enables bare instantiation. |
| 6 | Tak | The move-result message had a trailing comma, making `message` a 1-tuple (serialized as a list, e.g. `['Player 0 moved pieces from …']`) instead of a string; wrapping a `LocalizedMessage` in that tuple would crash JSON serialization. | Removed the trailing comma so it emits a proper (localized) string. | Yes — the move message is now a string, not a 1-element list. |
| 7 | LeducHoldem | `_legal()` returned Python `set`s. Set iteration order over strings is randomized per process (`PYTHONHASHSEED`), and that order feeds the user-facing "Valid actions: …" / "Illegal now. Allowed: …" banners — so the English output was non-deterministic across runs (a reproducibility bug for RL/eval; the golden could never be byte-stable without a fix). | Changed the three `set` literals to ordered `list`s (identical contents; `in` membership checks unaffected). | Yes — the allowed-actions banner now renders deterministically as a list (e.g. `['call', 'fold']`) instead of a randomly-ordered set repr. |
| 8 | Klondike | The turn-limit branch was an `elif ... >= self.max_turns:` placed AFTER an `else:` block at the same indent level — a `SyntaxError` that prevented the module from importing on ANY Python version (i.e. `Klondike-v0` could not be instantiated at all). | Re-indented the turn-limit `elif` and its body to attach to the inner `if self.klondike.is_won():`, restoring the intended forfeit / won / turn-limit three-way outcome. | Import-enabling fix — the game could not run at all before; no other logic touched. |
| 9 | Stratego | The flag-capture win reason was passed to `set_winner` as a 1-element **list** (`[f"...flag!"]`) instead of a string — it would not render via the LocalizedMessage path and is not JSON-serializable. (The other win reason was already a string.) | Changed the list to a plain `self.m(...)` string. | No visible change — English text byte-identical and this branch isn't reached in the golden; only the container type (list→string) changed so localization can render it. |
| 11 | WordChains | `__init__` built the sampling pool as `list(set(word.lower() for word in words.words()))`. Set iteration order over strings is hash-randomized per process (`PYTHONHASHSEED`), so `random.choice` picked a **different starting word on every run even with a fixed seed** — English output was non-reproducible (a reproducibility bug for RL/eval; the golden could never be byte-stable). | Changed `list(set(...))` to `sorted(set(...))`. Identical dictionary/validity and length filtering; only makes start-word selection deterministic under the seed. | Yes — the starting word is now reproducible (seed 42 → `deva`); no other logic touched. |
| 10 | UltimateTexasHoldem | env.py used Python 3.12 (PEP 701) nested same-quote f-strings at 6 sites (prompt `state_info` + FLOP/RIVER reveal messages) — a `SyntaxError` on Python 3.10/3.11, so the module could not import at all on the repo's interpreter. | Extracted a `_cards_str()` helper and passed the joined card string as a `{cards}`/`{hand}` slot. | No — rendered card strings are byte-identical; English golden byte-for-byte identical. (Separately, a pre-existing display bug where the rules pay-table prints literal `${self.ante_amount * 500}` from non-f-string literals was **preserved verbatim**, not fixed — out of scope.) |

## Ported (bigger change than a fix — flagged for maintainer review)

- **Coup** — could not run on the current codebase: `env.py` targeted an **older State API** (`ta.State(min_players=…, max_players=…)`, `state.reset(seed=…)`, `manually_update_current_player`, `prevent_player_change`, `add_observation(..., for_logging=…)` with no `observation_type`, `set_invalid_move(player_id=…)`); `env.reset()` raised `TypeError` immediately. It also had Python-3.12-only nested-same-quote f-string `SyntaxError`s. **Now ported** to `FFAMultiPlayerState` (~11 `add_observation` + ~12 `set_invalid_move` call sites reworked, the `prevent_player_change`→`rotate_player` turn/challenge/block control flow re-expressed, f-strings de-nested) **and fully localized** (8 languages). Verified behaviorally by driving full multi-turn games (action→block→challenge→resolution→elimination): coin deltas (income +1, tax +3, coup −7), influence loss on failed/succeeded challenges, block-then-challenge resolution, exchange (draw 2 / keep per remaining influence), and turn advancement all behave correctly; golden + 8-language smoke pass. **This is a from-scratch port with no upstream baseline to diff against — maintainers should sanity-check the turn/challenge/block control flow.** (It is *not* a Level-2 comms game — all actions are structured tokens.)

## Flagged, NOT fixed (out of scope for this PR)

- **IteratedStagHunt** — Level-2 communication game (deferred, see DEFERRED.md) that additionally has the same Python-3.12 f-string `SyntaxError`; left untouched.
